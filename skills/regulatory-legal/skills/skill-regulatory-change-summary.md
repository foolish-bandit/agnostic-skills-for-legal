# Skill: Regulatory Change Summary

## When to use this skill
Use this to produce a one-page change summary for an uploaded regulatory development, suitable for forwarding to an internal audience.

## Trigger phrases
- "One-pager on this rule"
- "Regulatory change summary"
- "Summarize this for the team"

## Required user inputs
- Uploaded regulatory document.
- Intended audience (executives, compliance, engineering, broad).
- Length preference (1 page default).

## Workflow
1. **Identification:** Title, issuing body, document type, effective date, comment deadline (if any), citation.
2. **TL;DR:** 3-5 bullets stating what changed, who is affected, and when.
3. **What's New:** Short prose section with section-cited details.
4. **Who's Affected:** Coverage / exemption summary with citations.
5. **What We Need to Do:** Plain-language internal action items (high level; the detailed tracker is a separate skill).
6. **Timeline:** Key dates with citations.
7. **Open Questions:** Items requiring follow-up.

## Output format: Change Summary (one page)
Use these section headers exactly:
- **Identification**
- **TL;DR**
- **What's New**
- **Who's Affected**
- **What We Need to Do**
- **Timeline**
- **Open Questions**

## Guardrails
- Stay at high level - this is a summary, not the obligations table or gap analysis.
- Cite the source document section for every factual claim.
- Match technical depth to the audience setting.

## Example starter prompt
"Write a one-page change summary of the attached EU AI Act delegated act for our executive team."
